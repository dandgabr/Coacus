# Feedback and postprocessing

Use feedback when what happens next depends on a previous frame. Use a composite when the output depends on sources rendered for the current frame. Keep scene ownership in the renderer and native controls in the DOM. For a reorder or route animation involving ordinary DOM content, use [view transitions](../../../../domains/design/ui-state-layout-transitions/references/view-transitions.md).

## Plan the passes

| Effect | Read | Write | Order |
| --- | --- | --- | --- |
| Fluid ink | Previous velocity and dye, latest pointer impulse | Next velocity and dye, then canvas | Advect and dissipate, inject impulse, constrain edges, swap, display |
| Persistent particles | Previous particles and optionally previous trail texture | Next particles and separate next trail texture | Update particles, decay previous trail, accumulate new marks, swap, display |
| Image transition | Current outgoing and incoming images, mask, progress | Composite output | Render sources, composite; at either endpoint, draw only the selected source |

For feedback, allocate two compatible resources per state field. Bind one as the source and the other as the destination. Swap them only after encoding the pass. Initialize both at allocation. Never attach a texture as the draw destination of a pass that samples it. Reserve previous-frame state for effects that require it. A plain mask only needs the two current images.

Decide the fallback before acquiring a backend. Start with visible HTML text, controls and a poster. Prefer WebGPU for new compute-heavy renderers. Request only the needed adapter features and limits, then check real texture formats, resource usage and pipeline creation. Use validation and allocation error scopes around controlled setup. Treat device acquisition failure and later device loss as separate events. Probe a WebGL2 implementation for the effect when available, and use a static swap or poster when neither implementation can draw. A renderer's fallback mode does not establish that its particular shaders, formats or passes work.

In WebGL2, enabling `EXT_color_buffer_float` makes formats including `RGBA16F` color-renderable. Check `checkFramebufferStatus` on **each** newly assembled target and after its replacement on resize. Check the actual formats and sampling filters independently. In WebGPU, give paired textures explicit sampling and storage or render-attachment usages and keep conflicting usages out of a single pass. Keep resource handles behind the renderer that created them. [Khronos floating color buffer extension, revision 8](https://registry.khronos.org/webgl/extensions/EXT_color_buffer_float/), [W3C WebGPU Candidate Recommendation Draft, 2026-11-16](https://www.w3.org/TR/2026/CRD-webgpu-20261116/)

## Low-resolution fluid ink

[Open the original ink implementation](../examples/feedback.html). The fixture packs signed 2D velocity and dye into an `RGBA16F` pair, caps the simulation's longest side at 128 texels and caps the output at a 960-pixel longest side and DPR 2. It uses semi-Lagrangian transport for a decorative field. A pressure projection and an incompressibility guarantee are outside this fixture's model.

1. Convert the latest primary pointer sample from the displayed stage rect to normalized texture coordinates. Invert Y for the WebGL coordinate mapping. Bound the impulse and use a native button for keyboard input. Disable it and hide drag instructions while the renderer is unavailable or motion is reduced. Horizontal dragging leaves vertical page scrolling available.
2. Sample the previous velocity at the current cell. Backtrace by velocity times the bounded time step, clamp the lookup between boundary texel centers and sample velocity and dye there. Apply exponential decay with time constants in seconds.
3. Inject signed velocity and dye near the pointer, then attenuate normal velocity near the edges. Hold the outermost cell ring at zero to confine the visual field. Swap the targets and sample the new state in the display pass.
4. Pause the clock when hidden. Restart from a bounded time step on return. Reallocate and clear feedback targets on resize. If preserving history is important, define and test an explicit resampling pass.
5. Stop requesting frames when the ink settles. Decrease simulation resolution first when the update pass costs too much. Reduce the display resolution when output fill rate is the limit.

[Mark J. Harris, *GPU Gems*, chapter 38](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-simulation-gpu) describes full stable-fluid passes, including pressure projection and boundary conditions. The fixture implements the smaller transport model above.

For persistent particles, cap the requested count by a measured quality budget and backend limits before allocation. For example, two buffers of 32,768 particles per buffer at 32 bytes each require 2 MiB total before trail textures. Keep age, position and velocity together, use a seeded launch phase and respawn or retire each particle after a bounded lifetime. Update in a fixed time step with a bounded number of catch-up steps. Batch visible marks into a draw when possible. Fade a separate trail pair in elapsed seconds and add the current marks after the decay pass. Keep normal playback GPU-resident; compare the same seeded state at fixed times at two refresh rates, with readback reserved for test probes. [WebGPU particle sample, checked 2026-11-27](https://webgpu.github.io/webgpu-samples/?sample=particles)

## Masked image transition

The fixture's Landscape images mode draws two procedural landscapes. At intermediate progress, draw Tide and Dawn into separate `RGBA8` targets, then draw one masked composite. The progress value stays in [0, 1]. At progress 0 or 1, draw only the selected landscape directly to the canvas. A reversal changes the destination while preserving the displayed progress. Rebuild both targets at the same output size after a resize, then reuse the current progress. Cache the two landscape targets until their inputs or dimensions change. While cached, draw only the composite at intermediate progress. With motion reduced or graphics unavailable, swap the DOM poster immediately and update the native scene name. [Three.js scene transition example, checked 2026-11-27](https://threejs.org/examples/webgpu_postprocessing_transition.html)

## Lifecycle and runtime checks

Assign ownership of the canvas, scene resources, observers, one pending frame and in-flight initialization to the mount lifetime. Keep a poster visible through acquisition and first-draw validation. On document visibility or intersection changes, cancel the frame if either condition blocks work, and check both again at entry to the callback. On loss, reveal the poster and drop renderer references. Only a newly created device or restored context can own replacement resources. Bound recovery attempts and abort or ignore a late asynchronous initialization after teardown. [WHATWG page visibility, checked 2026-11-27](https://html.spec.whatwg.org/multipage/interaction.html#page-visibility), [W3C Intersection Observer Working Draft, 2023-10-18](https://www.w3.org/TR/2023/WD-intersection-observer-20231018/), [Khronos context-loss extension, revision 15](https://registry.khronos.org/webgl/extensions/WEBGL_lose_context/)

Serve this package over local HTTP and open [the fixture](../examples/feedback.html) with `?checks` appended. A successful run checks delayed and failed acquisition, a real incomplete framebuffer, fluid-state readback, image pixels and pass counts, resize and reversal, then real offscreen suspension, context loss, recovery and teardown. WebGL2, float targets and the context-loss extension must be available for the positive controls. Run a second check with WebGL disabled to exercise actual backend unavailability. Test a real tab switch and record draw count and pending frames while hidden and after a visible resume. Check touch drag, keyboard controls, no script and a live reduced-motion preference change independently. Keep disabled graphics and reduced motion as distinct test cases.

Compare the same viewport and device with the active fixture and the same URL with `?static` appended. Record build-to-first-frame and teardown times separately from steady state, and collect frame interval percentiles, estimated missed refresh intervals, and CPU submission time with and without the effect. Keep those estimates distinct from compositor presentation and measured GPU execution. Measure GPU time only with an available timestamp mechanism and discard disjoint samples. If the target budget is missed, lower resolution or freeze; validate again on the intended hardware. [Khronos WebGL timer queries, revision 4](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/)

Test an idle display-density change with CSS size held constant. Re-arm the resolution query after each change, invalidate the drawing buffer through the same path as an element resize, and remove the query listener during teardown. If a target can change DPR without emitting either event, a low-frequency check while the canvas is mounted and visible can repair the stale buffer. Stop that check on hide, context loss and teardown. Submit frames only when dimensions change.
