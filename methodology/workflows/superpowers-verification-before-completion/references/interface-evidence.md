# Interface Evidence and Revision Scope

Use when a completion claim includes rendered interfaces or publication. Choose evidence for the actual claim:

- Follow [rendered interface verification](../../../../knowledge/skills/engineering/practices/ui-design-craftsmanship/references/rendered-interface-verification.md) for layout, paint, states and capture fidelity.
- Follow [rendered interface oracles](../../../../knowledge/skills/frameworks/framework-testing/references/rendered-ui-oracles.md) for readiness, controlled defects, inventory and measurement limits.
- Follow [published artifact verification](../../../../knowledge/skills/roles/devops-engineer/references/published-artifact-verification.md) for the approved revision, generated release and served dependency graph.

Keep the measured revision, sampled axes, inspected cases and capability limits with the conclusion. Reuse an unaffected result only with an explicit reason; rerun the evidence invalidated by a product change. Administrative promotion does not rewrite a historical result. A source scan, reasoning evaluation, automated rendering sample and human inspection establish different scopes.

Record old requirements as maintained, superseded or explicitly excepted by the appropriate authority. Release authorization does not create a missing performance or accessibility measurement. Do not repeatedly ask permission already granted for the same destination and scope, or expand a PR request into merge/install/deploy.
