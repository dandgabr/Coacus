# Testing Skills With Independent Agents

Use this reference when realistic agent behavior would add confidence to a complex or consequential skill change. Ordinary reference corrections can instead rely on source verification and focused retrieval/application checks. Follow the [behavioral validation contract](references/behavior-validation.md) for evidence depth and scope.

## Define the question before the test

Specify the decision the guidance should improve, the realistic input that exercises it and what observation could disprove the proposed rule. For discipline guidance, realistic time pressure or competing priorities can expose bypasses; references need accurate retrieval and application rather than artificial compliance pressure.

Keep user authority, side-effect limits and actual product requirements in the brief. A pressure scenario must not grant permission to change production, read credentials or destroy unrelated work. Prefer a bounded fixture or a reasoning-only decision when actions are outside the authorized evaluation.

## Run and preserve a baseline

Freeze the old guidance and record its revision. Give a fresh evaluator the realistic request and minimum raw artifacts. Do not include the intended solution, suspected failure or scoring answer. Capture the choices, reasoning and produced artifacts, then assess them against the rubric defined before the run.

A baseline may pass. Preserve that outcome and report that the probe found no observed behavioral defect; do not invent rationalizations, force a predetermined option or claim red-to-green improvement. A separate documented source contradiction or retrieval gap can still justify a scoped correction, with that limitation attached to the claim.

## Choose useful cases

| Skill purpose | Useful evaluation | Counterexample |
| --- | --- | --- |
| Discipline | Realistic conflicting demands and actual authorized action | A higher-priority user requirement legitimately changes the workflow |
| Technique | Apply the method to raw input, including a variation | An already-correct result needs no repair |
| Pattern | Recognize when the pattern applies | A neighboring problem needs another pattern |
| Reference | Find and accurately apply a relevant procedure | Missing information must remain unknown rather than invented |

Use enough variation and repeated samples for the intended confidence. A single pass does not establish reliability, and an arbitrary fixed repetition count does not replace a justified sampling design. A no-guidance control can help attribute the effect; report when attribution was not tested.

## Compare the candidate

Give a fresh context the same raw task and candidate guidance. Keep the author’s proposed answer out of that execution. Judge the outcome, not whether the response recites the new wording.

Record both successes and failures. If the agent disagrees, examine whether it found a real contradiction, missing condition or legitimate authority boundary before classifying its reasoning as evasion. An evaluator is allowed to falsify the proposed instruction.

For actual defects, revise the smallest instruction that changes the demonstrated decision and rerun the invalidated case. Keep a positive control so a guidance change that always refuses to act cannot pass a rejection-only scenario.

## Separate reasoning from execution

A diagnosis can be correct without a browser rendering, mutant execution, installation or deployment having occurred. State which depth the test reaches. For rendered UI use observable output and the [rendered interface oracle guidance](../../../knowledge/skills/frameworks/framework-testing/references/rendered-ui-oracles.md), not keyword presence alone.

When execution requires unavailable capabilities, record the unavailable portion. An unsupported measurement is not a pass. Restore each injected defect before another run and keep any evaluation artifacts in an isolated, ignored workspace.

## Review and stopping conditions

Ask an independent reviewer for concrete evidence of correctness or a counterexample, not an explanation of why a predetermined option must be obeyed. Review important findings, correct valid defects and preserve remaining limits.

Stop after the specified coverage and acceptance conditions are met, or report the concrete unresolved condition. Do not expand testing indefinitely to seek a flattering score. No finite pressure test proves a skill is universally resistant to failure.

## Completion record

Record the baseline/candidate revisions, raw inputs, rubric, exact responses or artifacts, outcomes, unavailable checks, source corrections and inspected scope. Examples from earlier campaigns are historical observations, not current results or universal instructions. A passing baseline followed by a passing candidate supports retained performance on that probe, not demonstrated improvement.
